# Plan: plugins

**Date:** 2026-06-05T13:22:00 | **Based on:** 2026-06-05T13:16:00_research.md | **Branch:** feat/plugins

## Architecture

### Summary
Add the Plugins extensibility layer to the existing Commons RN app (`packages/mobile`)
as four cooperating surfaces: a `lib/stores/plugins.ts` Zustand store (single source of
truth for install list + `developer`/`showWidgets` flags), shared presentational
`components/PluginWidget.tsx` + `components/PluginSlot.tsx` that Today/You drop in without
cross-feature imports, an isolated `features/plugins/` module (AppsScreen, PluginSheet,
DeveloperScreen) reached via two new thin Stack routes (`/apps`, `/developer`), and three
surgical edits to the demo-critical screens (More gains an "Apps & extensions" card + a
dev-mode switch; Today and You each drop one `<PluginSlot/>` element). Mock-data only:
"install" = a store toggle, no persistence, no OTA, no native modules. Registry frozen —
no 6th tab, no `lib/registry.ts` change; new **stack** routes only.

### Data Flow
```
lib/data/plugins.ts (PLUGINS, DEV_PLUGINS, PLUGIN_CATEGORIES, DEV_STATUS_TONE)
        │  seeds
        ▼
lib/stores/plugins.ts ── installed[] · developer · showWidgets · toggleInstall · setDeveloper
        │  read by (Zustand selectors)
        ├──────────────► components/PluginSlot.tsx ──renders──► components/PluginWidget.tsx
        │                       ▲ dropped into                         (next|list|stat|progress)
        │                       │
        │             features/today/TodayScreen  features/you/YouScreen   (surgical: 1 element each)
        │
        ├──────────────► features/plugins/AppsScreen ──opens──► features/plugins/PluginSheet
        │                       ▲ route /apps                          (toggleInstall)
        │                       │
        │             features/more/MoreScreen  (Apps row → /apps; dev-gated Developer row → /developer;
        │                                        "Developer mode" switch row → setDeveloper)
        │
        └──────────────► features/plugins/DeveloperScreen  (route /developer, gated on developer flag)
```

## Non-Goals
- No persistence (no AsyncStorage), no OTA/`expo-updates`, no real downloads — install is a store toggle.
- No 6th tab; no `lib/registry.ts` / `app/(tabs)/_layout.tsx` change — new **stack** routes only.
- No live data in widgets — `next.value` etc. are static mock strings (no timers/countdowns).
- "New plugin" CTA, Resources links, "Build your own" docs, and the Developer chevrons are no-ops.
- No bottom-sheet drag-to-dismiss; PluginSheet uses the existing scrim/X `components/Sheet`.
- No prototype Tweaks/postMessage host — the in-app "Developer mode" switch replaces it.
- No `features/plugins/manifest.ts` — the module adds no tab; entry points are More rows + slots + stack routes.

## Key Decisions
- **PluginSlot + PluginWidget live in `components/`, not `features/plugins/`** — Today/You drop the slot without violating no-cross-feature-imports (ADR-0001). Precedent: EventCard, NotificationsSheet promoted to shared layer for the same reason.
- **Slot filtering drives off the store's live `installed[]`, seeded from the static `installed:true` flags** — the prototype double-gated; RN uses one source of truth (the store) so install/remove reflects instantly across directory, sheet, and slots.
- **`developer`/`showWidgets` live in the plugins store as app-shell flags** (modeled on `lib/stores/ui.ts`), both default `true` — Developer console reachable and slots populated for the demo. A live "Developer mode" `Switch` in More replaces the prototype's non-portable Tweaks host.
- **New routes are stack pushes (`/apps`, `/developer`), mirroring `stipend/[id]`/`onboarding`** — registry stays frozen; only `app/_layout.tsx` gains two `Stack.Screen` lines.
- **Stream-by-stream, one commit per stream, blocking frontend-agent per dispatch** — commons-app retro: conductor failed 2/2, stream-by-stream 6/6. The 3 demo-critical edits are last and individually verifiable.
